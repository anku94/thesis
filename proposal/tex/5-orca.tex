\section{ORCA --- Generalizing Observability and
Control}\label{orca-generalizing-observability-and-control}

\subsection{Background and Motivation}\label{background-and-motivation}

\begin{itemize}
\tightlist
\item
  Lessons from CARP and AMR revealed the need for a general,
  programmable framework for both analytics and real-time control in
  large clusters.
\item
  Existing tools provided either narrow observability, limited
  programmability, or ad-hoc steering---none delivered unified,
  declarative, scalable control.
\end{itemize}

\subsection{Approach and Architecture}\label{approach-and-architecture}

\begin{itemize}
\tightlist
\item
  ORCA introduces a decoupled overlay network: application, aggregators,
  and controller communicate via high-performance RPC.
\item
  Built on distributed query planning (Apache DataFusion) for
  SQL-driven, in-memory analytics on streaming telemetry.
\item
  Real-time control via a Timestep-Linked Two-Phase Commit (TS2PC)
  protocol ensures consistent, synchronized updates across all ranks.
\end{itemize}

\subsection{Key Results and
Capabilities}\label{key-results-and-capabilities}

\begin{itemize}
\tightlist
\item
  Demonstrates scalable, low-overhead analytics at line-rate bandwidths,
  enabling ``analyze-then-persist'' at cluster scale.
\item
  Makes dynamic, cluster-wide control practical---enabling online
  tuning, interactive workflows, and safe application reconfiguration in
  situ.
\item
  Provides a declarative, extensible substrate for both scientific
  introspection and systems-level observability.
\end{itemize}
