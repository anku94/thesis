conditions unknowable before runtime, and that such conditions are systematically addressable
through adaptive mechanisms if the requisite feedback loops exist.

ORCA realizes a programmable tree-based overlay for in-situ analytics using OLAP primitives such as
columnar formats, SQL planning, and embeddable query engines.
Compared with prior in-situ HPC systems, ORCA differs in two ways.
First, it enables a hybrid execution model.
Instead of monolithic analytics placed entirely on application
ranks~\cite{Zheng2018:DeltaFS,Jain2024:CARP} or entirely offloaded to a
dedicated tier~\cite{Eisen2024:ADIOS}, ORCA uses a planner to decompose analytics into operators
that can be placed on
either tier at runtime.
Second, unlike ADIOS-style offload as a peer MPI job~\cite{Eisen2024:ADIOS}, ORCA’s analytics tier
is completely asynchronous while still preserving timestep-consistent analytics semantics.

\section{Steerable Observability: Retrospective and Synthesis}\label{sec:concl:retrospective}

We define steerable observability as the ability to request runtime views of application state,
reconstructed in real time, with the ability to change requested views on demand.
This makes always-on collection viable for production BSP systems: high-level signals
flag anomalies in real time, and narrower views can then surface their root causes.
The same paradigm enables online intervention, as views are both necessary to guide interventions
and
assess their effectiveness.

\paragraph{BSP Is Different}
BSP workloads run as a single coordinated job, not a web of loosely coupled microservices.
Global synchronization defines both the unit of work and the axes of causality and consistency.
Attribution of pathologies is first to a straggler rank, then to the sequence of events behind its
slowdown.
Root causes lie within a deeper layer of the same runtime stack, not across microservices.
Analyses need to preserve these causal dependencies.
Event-based streaming systems treat
events as separate in transit, requiring these dependency edges to be reconstructed after
collection.

ORCA is co-designed for this paradigm, translating queries into an execution strategy
that approaches the minimum necessary work --- data movement is minimized via pushdowns that
leverage the application's scale, and RDMA minimizes
the overhead of residual data movement.
All processing happens in-memory over a highly efficient columnar representation.
The closest analogs are \emph{Data Acquisition} (DAQ) pipelines in particle accelerators, where
FPGAs discard the bulk of sensor data at source, retaining only high-signal telemetry.
Fay and Snicket implement query-driven tracing for microservices.
ORCA extends this to BSP workloads, adding a
control plane for steerability.

\paragraph{Steerability Limits
}
Steerability is bounded by loop latency.
ORCA lowers this latency by eliminating unnecessary data movement, serialization, and ETL costs,
but fundamental bounds remain.
In some regimes, global views cannot be assembled on the decision timescale --- network congestion
control is designed explicitly around partial observability.
Even where views are timely, interventions are only viable if conditions persist long enough to act
on.
When they do not, the same analytics layer still enables offline characterization to inform
predictive mechanisms.

\section{Immediate Extensions}\label{sec:concl:extensions}

\paragraph{Instrumentation Sources}
Tools like Kineto aggregate telemetry from multiple sources into a unified trace.
ORCA supports the same but as real-time aggregations over any interface that emits structured
events---NVTX/CUPTI GPU hooks, MPI runtime probes, hardware counters.
eBPF and DynInst are especially appealing as they enable dynamic instrumentation without
recompilation, extending visibility into arbitrary functions at runtime.

\paragraph{Approximate Summaries}
Mergeable sketches can summarize streams in-flight at far lower cost and fit naturally into ORCA’s
reduction topology.
For example, KLL or t-digest can estimate latency percentiles, and Count-Min or SpaceSaving can
identify heavy hitters such as straggler ranks or hottest callsites, all with bounded error and
without aggregating raw events.

\paragraph{Shuffling-Based Streaming Analytics}
Shuffling-based in-situ indexing systems like DeltaFS and CARP show that hash and range
partitioning can reorganize scientific data effectively at scale.
ORCA can treat these shuffles as intra-tier operators within its topology, so they compose cleanly
with inter-tier reductions in a single plan.
Because the MPI tier has substantial egress bandwidth during checkpointing, the planner can be
phase-aware, scheduling shuffle sinks at the MPI tier in checkpoint phases while avoiding that
interference during compute phases.

\paragraph{Open Table Formats for HPC}
While ORCA writes telemetry as partitioned Parquet, it does not currently emit a metadata catalog.
Open table formats such as Iceberg maintain a lightweight index over partitioned Parquet
files---partition boundaries, column statistics, file locations---enabling engines to prune
irrelevant data without scanning.
Any HPC pipeline that already writes Parquet would benefit from the same treatment, replacing ad
hoc file-management conventions with self-describing, immediately queryable datasets.

\paragraph{Control Interface Regularization}
The set of controllable actions is currently defined ad hoc per integration.
Regularizing this into typed providers that advertise capabilities, accept structured commands, and
return typed acknowledgments makes control capabilities discoverable and composable, analogous to a
southbound
API in SDN.

\section{Future Directions}\label{sec:concl:future}

\paragraph{Beyond Relational Algebra}
Relational operators fit event telemetry, but they are a poor match for the structured objects that
dominate scientific computing and ML.
Arrays and meshes have dimensionality, adjacency, and layout that determine both meaning and
efficient access, and flattening them into tables discards that structure.
A natural extension is a multi-algebra planner that keeps relational operators for event streams
but adds array and mesh operators for structured data, composed in one plan.
Interop is becoming practical via Arrow bridges such as Arrow Zarr for arrays and Arrow DLPack for
tensors.
With operators over structured scientific data, visualization workflows also become expressible via the
same dataflow, rather than as a separate analytics pipeline.
Another motivating example is observability over GPU-resident tensors, such as computing a histogram of
weight values.
Supporting device-side reductions that emit only compact summaries is an interesting extension
beyond relational processing.


\paragraph{Multi-Tier Compilation}
ORCA’s topology can be extended with extra execution tiers, such as sandboxes and SmartNIC
aggregation points, turning query execution into a multi-target compilation and placement problem.
eBPF and DPUs then become execution tiers: eBPF runs bounded per-event logic at capture such as filtering,
while DPUs run limited-state streaming transforms, and higher tiers handle heavier operators such as joins and windowed aggregation.
The interesting direction is lowering a high-level query into tier-appropriate kernels with
explicit materialization points while preserving BSP phase semantics and staying within jitter and
overhead budgets.

\paragraph{Cost-Aware Reactive Placement}
ORCA’s placement today follows tree the topology: per-partition work is pushed down, while
cross-partition work remains at higher tiers.
While this works, it is not cost-aware because it does not react to observed placement conditions
such as backlogs and kernel costs.
A natural extension is to feed these cost signals back into the planner and let it move operators
and sinks across tiers online.
This effectively makes ORCA self-tuning using the same observability machinery it provides to
applications.
